# Token is Gold: How to Save up to 90% of Tokens in AI Development

If you heavily use AI assistants for programming, you have likely encountered two major problems: "inflation" in your token bill and "context rot", where the AI begins to forget rules and hallucinate after a few interactions.

To solve this, this guide will teach you how to install and configure the three most powerful tools available today ([Graphify](https://pypi.org/project/graphifyy/), [RTK](https://rtk-ai.app/), and [GSD Core](https://www.npmjs.com/package/@opengsd/gsd-core)) across three different environments (Claude Code, OpenCode, and Antigravity CLI). Additionally, we will configure global rules to enforce the use of sub-agents and early context compaction.

---

## 1. Graphify: The End of Blind Searches

**[Graphify](https://pypi.org/project/graphifyy/)** replaces reading raw files with a semantic and structural knowledge graph. When you ask a question about the project, instead of the AI running a grep and reading dozens of entire files, it queries this compact graph.

**Why does it save tokens?** By allowing the AI to navigate through connections (nodes and edges) instead of long texts of code files, Graphify can reduce token consumption by up to **71.5 times** per query.

### How to Install and Use

First, install the CLI globally on your machine using your preferred package manager (e.g., UV or pip):

```bash
pip install graphifyy
```

- **In Claude Code:** At the root of your project, run `graphify claude install`. This will create a `CLAUDE.md` file and a `PreToolUse` hook that forces Claude to consult the graph before attempting to read your files.
- **In OpenCode:** Run `graphify opencode install`. This will write the instructions directly into your project's `AGENTS.md` file.
- **In Antigravity:** Graphify does not yet have an automatic installer for Antigravity listed in its commands. To use it, you must generate the graph by running `/graphify .` and manually include instructions in your Antigravity rules file (usually `.agents/rules/`) so that it always reads the `graphify-out/GRAPH_REPORT.md` file before performing searches.

## 2. RTK (Rust Token Killer): The Terminal Filter

**[RTK](https://rtk-ai.app/)** acts as a lightning-fast proxy (intermediary) in your terminal. Whenever the AI attempts to run commands with massive outputs (like `npm install`, `git status`, `cargo test`), RTK intercepts, filters out the "noise," and returns only the essential information to the context window.

**Why does it save tokens?** RTK generates direct savings of **60% to 90%** (reaching 99% in testing commands like jest or vitest) in consumption generated by terminal outputs.

### How to Install and Use

To install the base tool on Mac/Linux:

```bash
curl -sSL https://rtk-ai.app/install.sh | bash
```
*(On Windows, download the binary and place it in your PATH, or use WSL for full hook support).*

Once installed, configure it in your agent:

- **In Claude Code:** Run `rtk init -g`. This configures the native hook.
- **In OpenCode:** Run `rtk init -g --opencode`. RTK will be installed as a TypeScript plugin in OpenCode.
- **In Antigravity:** Run `rtk init --agent antigravity`. RTK will add instructions to the `.agents/rules/antigravity-rtk-rules.md` file to guide the AI.

## 3. GSD Core (Get Shit Done): The Sub-agent Maestro

**[GSD Core](https://www.npmjs.com/package/@opengsd/gsd-core)** is a framework focused on specification-driven development. It breaks large tasks into atomic plans that are executed in parallel windows.

**Why does it save tokens?** It solves "context rot". Instead of clogging the main session with code executions and error logs, GSD isolates these heavy tasks by delegating them to sub-agents that start with a 100% clean context window (up to 200k tokens). Your main window remains operating between 30% and 40% capacity, functioning at maximum quality without accumulating garbage from previous conversations.

### How to Install and Use

Installation is identical for any of the 3 assistants, as GSD uses a universal interactive installer. In your project's terminal, run:

```bash
npx @opengsd/gsd-core@latest
```

> **Note:** The tool was recently renamed from `get-shit-done-cc` to `@opengsd/gsd-core`.

During the interactive wizard, the installer will ask for your AI environment (runtime). Simply select Claude Code, OpenCode, or Antigravity CLI from the provided list, and the installer will handle all the adaptation automatically.

Then, just use the standard 5-step flow commands, such as `/gsd:new-project`, `/gsd:plan-phase`, and `/gsd:execute-phase`.

## 4. Global Instructions: Forcing Sub-agent Usage

Even without running the full GSD flow all the time, you can (and should) instruct your AI assistant to delegate manual work to preserve context.

**How to do it:** Locate your project's base memory file. In Claude it's `CLAUDE.md`, in OpenCode it's `agents.md`, and in Antigravity these are the `.agents/rules/*.md` files. Add the following rule block:

> **Global Architecture Rule:**
> "Whenever you are in edit/build mode, never implement features yourself in the main context window. Use sub-agents or background agents at all times to delegate tasks (such as research, refactoring, and implementation). Act only as a coordinator. Sub-agents must execute the task in parallel whenever possible and return only the final summary of what was done to the main session."

**Token impact:** Because the sub-agent does not pollute the main context window with failed code attempts or huge execution outputs, your main session spends a minimal fraction of tokens to understand that the task was completed successfully.

## 5. Global Instructions: Early Context Compaction

With the massive context windows of current models, the AI tends to passively accumulate conversation history. To keep consumption cheap and intelligence sharp, we must force the AI to self-compact early on. In the OpenCode and Claude ecosystem, there is a mega-optimization package called "Everything Claude Code" that has proven the value of this tactic.

**How to do it:** Add this rule to your main memory file (`CLAUDE.md` in Claude Code, `agents.md` in OpenCode, or in Antigravity rules) to program the AI to self-manage:

> **Global Context Management Rule:**
> "Actively monitor your context window usage. When it reaches 50% capacity, stop and perform a context compaction (or prompt the user to run the compaction tool). Summarize architectural decisions and the current state of the task, preserving only technical highlights and discarding previous attempts and conversation logs to free up space."

In addition to automated instructions, you can act manually throughout the session:

- **Compaction Command (`/compact`):** In Claude Code, whenever you feel the conversation has dragged on too long, you can run this command (e.g., `/compact preserve only architectural decisions`) for the AI to summarize the session up to that point and delete the rest.
- **Clear Commands (`/clear` or `/new`):** Started a new feature? Don't continue in the same chat! Use `/clear` in Claude Code or `/new` in OpenCode to wipe the window and start with fresh memory. The GSD framework encourages that no session relies on a long chat history, keeping everything saved only in files on disk (like the `.md` files in the `.planning` folder).

**Token impact:** The strategy of triggering compaction early (when context hits 50%) combined with *thinking tokens* limits cuts costs by about 60% without losing quality in tasks (as demonstrated by the Everything Claude Code system). Furthermore, the GSD documentation warns that the AI's maximum reasoning quality only occurs when the context is between 0 and 30%. Past 50%, the AI already starts cutting corners.

## Conclusion: The Secret is Context Engineering

Coding with AI is no longer just about "writing good prompts". It has become **context engineering**.

- **Graphify** prevents the AI from reading and processing garbage by opening unnecessary files, reducing search costs by up to 71.5 times.
- **RTK** cuts the absurd noise that terminal outputs throw directly into context, filtering out 60% to 90% of logs.
- **GSD Core** solves "context rot," isolating complex executions to sub-agents that are born and die with 100% clean windows.

Combine these three approaches in Claude Code, OpenCode, or Antigravity, apply the global rules, and you will transform assistants that previously became "dumb and expensive" throughout the day into a scalable, relentless, and extremely cost-effective production line!
